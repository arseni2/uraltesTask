# Тестовое задание — Поиск автозапчастей (Favorit-parts)

Тестовое задание для вакансии **Frontend-разработчик (React + вёрстка)** — ООО «ЮРАЛ» (Favorit-parts).

Одностраничное приложение для поиска автозапчастей по артикулу через веб-сервис «Проценка»:

1. **Этап 1.** Пользователь вводит артикул детали → выполняется запрос к API → отображается список производителей (брендов), выпускающих деталь с данным артикулом, с ненулевым остатком.
2. **Этап 2.** При выборе производителя выполняется повторный запрос (`brand` + `analogues=on`) → отображается таблица найденных аналогов и предложений: наименование, производитель, артикул, цена (минимальная по складам с остатком), доступный остаток, признак «невозвратная позиция».

## Стек

- **React 19** (функциональные компоненты, hooks) — без TypeScript
- **Redux Toolkit** + react-redux — управление состоянием, `createAsyncThunk` для запросов
- **Vite** — сборка и dev-сервер, алиас `@` → `src/`
- **Bootstrap 5** — стилизация (адаптивная сетка, компоненты: forms, list-group, table, spinner, alert, badge)

## Запуск

```bash
npm install
npm run dev      # dev-сервер на http://localhost:5173
npm run build    # production-сборка в dist/
npm run lint     # oxlint
npm run preview  # предпросмотр production-сборки
```

## Логика работы с API

- Базовый адрес: `http://api.favorit-parts.ru/hs/hsprice/` (задаётся через `.env`)
- **Этап 1:** `GET ?key=...&number=...` — из ответа извлекаются уникальные бренды с `count > 0`
- **Этап 2:** `GET ?key=...&number=...&brand=...&analogues=on&info=on` — вложенный массив
  `analogues` раскатывается в плоский список; оригинальная позиция помечается бейджем «исходная»
- Цена берётся из `warehouses[].price` (верхнеуровневый `goods.price` устарел — не используется),
  для позиций с остатком отображается минимальная цена по складам
- Спецсимволы в `number`/`brand` кодируются через `encodeURIComponent`

## Тёмная тема

- По умолчанию тема следует системной настройке (`prefers-color-scheme`)
- Кнопка ☀/🌙 в шапке переключает тему вручную; выбор сохраняется в `localStorage`
  и после перезагрузки страницы имеет приоритет над системной
- Используется встроенный механизм Bootstrap 5.3 — атрибут `data-bs-theme="dark"` на `<html>`
- Мета-тег `theme-color` перекрашивает браузерную панель мобильных устройств под тему

## Адаптивность и UI/UX

- **Мобильные (<576px):** предложения отображаются карточками (название, бренд,
  крупная цена, остаток, бейджи), кнопка поиска на всю ширину, крупные тап-таргеты (≥48px),
  safe-area отступы для устройств с «чёлкой»
- **Десктоп (≥768px):** двухколоночный layout (производители слева, таблица справа),
  таблица со sticky-заголовком, hover-подсветкой строк и цветовым акцентом цены
- **UI/UX:** шрифт Inter (локально через `@fontsource`, без CDN), иконки Bootstrap Icons,
  степер этапов поиска, скелетоны (Bootstrap placeholder) вместо спиннеров во время загрузки,
  карточки брендов с аватаром-инициалом, сводка «от X ₽ / всего N предлож.»,
  пустые состояния с иконкой и кнопкой «Новый поиск», плавные переходы при смене темы,
  focus-visible кольца и `prefers-reduced-motion`

## Обработка состояний и ошибок

- Отдельные статусы загрузки для каждого этапа (`idle / loading / succeeded / failed`) —
  на время запроса показывается спиннер
- Ошибки API (поле `error` в ответе: `Empty key!`, `Invalid key client!`, `Request quota exceeded!` и др.)
  выводятся в alert с текстом от сервиса
- Пустой ответ (товар не найден — массив с одной пустой структурой) → информационное сообщение
- Позиции без остатка (`warehouses` пуст / `stock = 0`) отфильтровываются
- Сетевые сбои и некорректный JSON → понятное сообщение об ошибке
- Повторный поиск сбрасывает состояние предыдущего (бренды, выбор, предложения)

## Примечания

- API доступен из браузера напрямую: сервис отдаёт `Access-Control-Allow-Origin: *`, прокси не требуется
- Тестовые артикулы для проверки: `01089` (есть остатки у ASAM, FEBI, GLASER, Meat & Doria),
  `7160500039S`, а также заведомо несуществующий номер для проверки пустого ответа
